# Build manifest

One goal: no positional or knowledge question has more than one implementation, and completion offers every symbol kind the knowledge tier answers.
One signal: both baseline files are deleted, and the issues named below are closed.

## Rules

- Until every box below is ticked, this list is the only work. Nothing outside it starts unless the human schedules it directly.
- One step is one PR on branch `step/<n>`.
- Steps run in order. Step n starts when step n-1 has merged.
- The PR for a step ticks its own box. A ticked box means merged.
- The rule set is closed: no new PHPStan rule, deny entry, deptrac edge, allowlist path, baseline entry, `@phpstan-ignore`, or RFC amendment, except a Tighten or Lateral edit that the step's row names (that naming is the human's authorisation under `enforcement-edits.md`). Removing any of those is always allowed. A gap found on the way becomes a GitHub issue.
- A step's `Done` clause is its whole acceptance. A reviewer checks that clause and nothing else.
- Background reading is RFC 1 §4 (the invariants). Plan 0002 is history, not work.
- One route per fact, in one shape. Where a fact has, or could have, more than one complementary implementation (a parsed tree and a skeleton, an open document and a file on disk, a cache and what it caches), the code has exactly one interface for that fact in `src/`. Every implementation implements it, including the composite and any decorator. The composite, always named `Composite<Interface>`, is the one implementation that holds an ordered `iterable` of the interface (so a container's tagged collection plugs in unchanged) and answers by asking its members in order: a lookup returns the first non-null answer, an enumeration merges every answer with the earlier member winning a name clash, and it holds no other logic. It is what a consumer receives at the root, and it is how a fact with several routes reaches a consumer as one. A decorator (a cache, a memo) implements the interface and wraps one. A consumer is typed on the interface, holds one of it, and never names an implementation; the composition roots (`Server::forProject` and `KnowledgeStack::forProject`, the hand-written container, which a real container replaces line for line) are the only places that do; a test that needs production wiring gets it from a factory under `tests/`, never from a factory in `src/`. `NamespaceCatalog` with `CompositeNamespaceCatalog` and `CachedNamespaceCatalog`, and `SymbolLocator` with `CompositeSymbolLocator`, are the shape today; a consumer that names an implementation, calls a static method on one, or holds two routes to one fact has moved the problem, not removed it. The interface, its composite, and every implementation share one namespace named for the interface under the tier that owns it (`Knowledge\SymbolLocator\`); step-52 moves today's families, and a family a later step creates starts there. Syntax has one node model, php-parser's: `SyntaxSource` returns php-parser nodes, and an implementation built on another parser converts its tree into that model rather than the positional layer learning a second one. Changing the model is an RFC amendment, not a step. `OneRoutePerFactTest` (step-32) derives every implementation from the interface, checks the composite's name and the family's namespace, and fails when anything but the root names an implementation; a step that adds an implementation adds it to the root and nowhere else.
- A skipped test case runs its assertion first and skips only when the assertion fails; a listed case whose assertion passes fails the test, so the entry leaves with the fix. A skip that runs before its assertion hides a green cell and is a finding.
- A test that tells states or routes apart by fixture pins each state's defining property with its own assertion, and its fixtures differ only in that property. A fixture chosen because it exists, rather than because it fits the row's own words, is a finding.
- A row states facts about the code. If a fact the row states is false, or a thing it names does not fit the row's own words, the implementer stops and reports; choosing an interpretation is not an option.
- Regex stays in the files `phpstan.neon` allows it in.
- A file move (a rename, or a move into a family namespace) carries its `phpstan.neon` allowlist paths with it, which `enforcement-edits.md` classifies as Lateral. It adds no `deptrac.yaml` edge and no allowlist path: the layer collectors are directory globs, so a move within a tier needs no edit, and a move across tiers is made only where the ruleset already allows every dependency the class has. A move that would need a new edge or path is not made; the class, not the ruleset, is wrong.
- When step-53 lands, this file and its two driver skills are gone, and work returns to plain issue flow: pick an issue, "do #xxx".
